# Primeira Liga — аналитика матчей

Прогнозирование исходов матчей португальской Primeira Liga на данных 27 сезонов
(2000/01 – 2026/27) с честной оценкой качества против закрывающей линии
букмекеров.

## Главный результат

На отложенных тестовых сезонах (2023/24 – 2025/26, 918 матчей):

| | log-loss ↓ | точность |
|---|---|---|
| наивный baseline | 1.07834 | 42.6% |
| Elo | 0.96468 | 53.3% |
| **Dixon-Coles** | **0.93556** | 55.9% |
| рынок (закрывающие, без маржи) | 0.90877 | 57.2% |

Модель уверенно обходит наивный baseline, но **уступает закрывающей линии
букмекеров на 0.027 log-loss**. Это показано на сайте, а не спрятано: рынок
получает информацию о составах, которой в бесплатных источниках нет.

## Структура

```
etl/            сбор и нормализация данных
  config.py       сезоны, пути, код соревнования
  teams.py        справочник клубов (43 команды, разные написания)
  fetch_csv.py    football-data.co.uk — история, статистика, коэффициенты
  fetch_api.py    football-data.org — расписание, таблица (нужен токен)
  normalize.py    единая схема, слияние источников
  validate.py     проверки качества, пайплайн падает при нарушении
  run.py          точка входа

models/
  poisson.py      общие пуассоновские помощники
  elo.py          Elo с онлайн-калибровкой коэффициента
  dixon_coles.py  пуассоновская модель с поправкой на низкие счёты
  market.py       снятие маржи: power, Shin, пропорциональный
  market_calibration.py  выбор метода снятия маржи по данным
  backtest.py     метрики: log-loss, Brier, точность, ROI
  backtest_runner.py     walk-forward с разделением подбор/оценка
  predict.py      прогнозы на будущие матчи

web/            витрина на Next.js 15 + Tailwind 4
.github/        автосбор по расписанию + проверка сборки фронта
```

## Запуск

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# токен football-data.org — только для расписания будущих матчей
cp .env.example .env   # вписать FD_ORG_TOKEN

python -m etl.run                     # скачать и нормализовать
python -m models.market_calibration   # выбрать метод снятия маржи
python -m models.predict              # прогнозы на ближайшие туры
python -m models.backtest_runner      # метрики (медленно, ~5 мин)

cd web && npm install && npm run dev  # витрина на :3000
```

Артефакты пайплайна (`predictions.json`, метрики) кладутся в `web/public/data`
коммитом из GitHub Actions — витрина читает их оттуда.

## Принципы, которые нельзя нарушать

**Никаких утечек из будущего.** Каждая модель обучается только на матчах,
сыгранных до прогнозируемого. Dixon-Coles переобучается раз в 30 дней на
шестилетнем окне. Вес бленда подбирался на сезонах 2019/20 – 2022/23 и не
подгонялся под тестовые 2023/24 – 2025/26.

**log-loss вместо «точности».** Точность в 55% звучит солидно, но она
нечувствительна к качеству вероятностей. Основная метрика — логистика,
она штрафует за уверенные неверные прогнозы.

**Коэффициенты не равны вероятностям.** В них заложена маржа ~6.2% и
искажение в сторону фаворитов. Метод снятия маржи выбирается по калибровке
на данных, а не по умолчанию; см. `models/market_calibration.py`.

**Структура колонок меняется между сезонами.** От 22 до 119 колонок.
Парсер читает строго по заголовкам, никогда по индексам.

## Что улучшать дальше

Разрыв с рынком — не приговор, а конкретный список отсутствующих признаков:
форма за последние 3–6 матчей, дни отдыпа и конфликт календаря, доля голов из
ударов в створ, динамика силы по xG, бустинг поверх Dixon-Coles с калибровкой.
